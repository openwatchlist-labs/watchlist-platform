# Security policy

Do not open a public issue for a suspected vulnerability. Use GitHub private vulnerability reporting for `openwatchlist-labs/watchlist-platform` and include affected version, reproduction steps, impact, and any proposed remediation.

Supported security fixes target the latest release candidate and the latest accepted phase tag. This project handles compliance-sensitive workflows; reports involving tenant isolation, token validation, audit integrity, idempotency, catalog activation, policy mutation, path traversal, secret exposure, or unsupported LLM claims receive priority.

Never submit real customer payment messages, watchlist-provider licensed data, credentials, private keys, database dumps, or confidential investigation records in a report.
