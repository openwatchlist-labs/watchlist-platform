# Legacy repository disposition

`openwatchlist-labs/watchlist-platform-legacy` preserves the complete
pre-clean-restart history of OpenWatchlist. Its immutable archival boundary is:

- final freeze commit: `31aa23f516018f7577f4dcec95142f981142a6f8`;
- reviewed source tree: `cd6e0d80584c05bde3a14582ab895b6e4ed79df3`;
- canonical successor: `openwatchlist-labs/watchlist-platform`;
- target visibility: private;
- target state: archived and read-only;
- GitHub Actions: disabled;
- new development, releases, and deployment use: prohibited.

The legacy repository remains available only to authorized maintainers for
provenance reconstruction, incident review, and historical comparison. It is
not a source of current code, configuration, qualification, release, or
operational instructions.

## Archive sequence

The repository is made private and archived only after this governance record
and the sanitized qualification lineage are merged into canonical `main`.
Before mutation, the archive procedure creates and validates a local mirror,
Git bundle, ref inventory, repository metadata snapshot, and SHA-256 manifest.
It verifies the exact freeze commit and refuses mutation on ref drift, open pull
requests, forks, or an unmerged canonical lineage record.

## Retention boundary

Retain privately:

- complete Git refs and object history;
- historical source, workflows, and tags;
- authorized private evidence outside canonical Git;
- the locally verified mirror and bundle generated by the archive procedure.

Do not copy into canonical Git:

- raw test output or evidence archives;
- generated candidate sets, selectors, plans, or materialized execution trees;
- private infrastructure identities, credentials, runtime state, or logs;
- fixed-host deployment configurations;
- tests for code that was not imported into the canonical repository.

Changing repository visibility does not retract material that was previously
public. Credential rotation and any required history-removal process remain
separate security controls.
